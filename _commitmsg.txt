fix(core): stop silent data loss and wrongness in consolidation

Found by a repeat audit of the business logic; every item was reproduced
before and after the fix.

Silent data loss, the same defect in two paths:
- the consolidation UPDATE branch wrote existing details, owner,
  description and mitigation through _value(new_item, key), whose
  implicit default is an empty string, so any field the plan did not
  mention was erased. status, impact and due_date already read the
  current value; this brings the other four in line.
- the fallback path had the identical bug in six places, and an absent
  due_date also cleared the stored date.

Idempotency and state machine:
- the decisions loop used get("decisions", []) where its three sibling
  loops use "or []", so an explicit null reached iteration as None and
  raised TypeError, which the API layer does not catch.
- a short embedding batch is now a ValueError instead of a silent gap,
  because the caller matches vectors to items positionally.

Upload boundary:
- a .docx that is not a ZIP and a malformed .pdf raised BadZipFile and
  PdfStreamError, neither of which the except tuple caught, so a
  malformed upload returned 500. Both now map to the ValueError the API
  already turns into a 400.
- MAX_EXTRACTED_CHARS caps the inflated result. The 20 MB guard only
  measures the compressed stream, so a small docx could expand to tens
  of megabytes of text.

External calls:
- @retry had no reraise, so an exhausted retry raised RetryError, which
  the API layer does not catch: a 429 upstream returned 500 instead of
  the documented degraded 201.

Also removed document_parser_constants.py, an unimported duplicate whose
comment claimed a Flask body cap that does not exist.

Tests, 64 increased to 76:
- a nullability contract mapping every column to its Mapped annotation,
  which is the assertion whose absence let the mapped_column migration
  ship a NOT NULL column,
- regression tests for each fix above,
- real DOCX and MD uploads, which the advertised formats never had.

Measured: ruff clean, mypy 0 errors on 12 modules, 76 tests pass,
coverage 82 percent to 86 percent overall, project_memory 41 to 52,
document_parser 52 to 71.
